### In plain words

You hold your phone over the sticker, take a picture, and the app reads it like a human expert would: *"This is a Buderus boiler, model G-524-558, made around 1998, burns gas, 558 kW."* It then looks the unit up in a **catalogue of ~132,000 registered heating products** (the official European EPREL registry) and shows you the matching entries with a confidence score. If the unit is too old to be in the registry, it keeps searching the public registry online and the manufacturers' own websites. The whole thing is finished, logged at 402 hours, and covered by 102 automated tests — and it has a proper user interface in German and English, with camera support, GPS location, data-privacy consent, and a picture guide that shows where to find each field on a nameplate.

### Dataset finding (14 EVH nameplates, 7 brands)
- Only **~1 clean EPREL hit** in the whole set.
- **Pre-2014 units are legally absent from EPREL** — a German market reality, not a tool flaw.
- Consequence: the **Local DB → EPREL → website fallback chain** does the heavy lifting for most real units.
- State this limitation honestly and early — it positions the tool correctly as "finds *most* older units via fallback, and modern registered units exactly."

### In plain words
> The tool works on two kinds of pictures: the clean photo a technician takes of a new boiler's sticker, and the messy, blurry photos of old paper inspection reports. For clean stickers it reads the number plate almost perfectly (98.6% confidence). For old units from the 1990s, it still reads the brand and model — but the official EU registry simply has no entry for them, because only products sold after 2014 must be registered there. So for most old boilers in German homes, the tool finds the right *brand* and *model* and matches it against the database and the manufacturer's website instead of the EU registry. That's not a bug — it's the law.

## 3. Backend code walkthrough (~10–15 min, real code, no cleanup)

> No pre-cleaning or extra comments were added, as requested. Files below are the real, working code.

### Technical map
| Module | What it does |
|---|---|
| `app/main.py` | FastAPI app, CORS, scheduler startup, serves frontend at `/` |
| `app/api/ocr.py` | Upload endpoint (JPEG/PNG/WebP/PDF, multi-image) |
| `app/services/ocr_service.py` | Orchestrates OCR pipeline, persists results, calls matching |
| `app/ocr/preprocessor.py` | OpenCV: perspective/contrast/rotation fixes |
| `app/ocr/reader.py` | Client for the isolated OCR subprocess (`ocr_worker.py`) |
| `app/ocr/parser.py` | Extracts brand/model/energy class/kW/fuel from raw text |
| `app/services/matching_service.py` | **Brand-consistency gate** (kills cross-brand false positives) + fuzzy scoring |
| `app/services/crawler_service.py` | EPREL crawl (128k records), on-demand search, kW-range + fuel-type filtering |
| `app/scheduler.py` | Daily refresh (off by default) |
| `app/services/manufacturer_scraper.py` | 19+ brand-site scrapers |

### Walkthrough order & what to point at
1. **`app/main.py`** → app setup, CORS, lifespan (scheduler startup).
2. **`app/api/ocr.py`** → upload → `ocr_service.py` → `app/ocr/` (preprocessor → reader → parser).
3. **`app/services/matching_service.py`** → show the brand-consistency gate: the fix that stopped "Truma" from matching TERMIA/TRANE junk (a real bug found in field testing).
4. **`app/services/crawler_service.py`** → EPREL crawl + on-demand fallback + kW/fuel filtering.
5. **`app/services/manufacturer_scraper.py`** → 19+ brand site scrapers.

### In plain words
> Think of the code as a small factory line:
> 1. **Front door (`main.py`)** — the whole factory's reception; checks who's allowed in and starts the daily maintenance timer.
> 2. **Photo intake (`ocr.py`)** — receives the picture.
> 3. **Reading station (`ocr_service.py` → preprocessor → reader → parser)** — first straightens and sharpens the photo, then "reads" the letters, then picks out the fields: *who makes it, which model, what class, how many kW, what fuel*.
> 4. **The library lookup (`matching_service.py`)** — searches the 132,000-product catalogue. The important safety rule here: *only match if the brand really agrees*. Earlier the tool once matched a caravan heater ("Truma") to totally different brands just because the codes looked similar — that was fixed.
> 5. **The librarian's assistant (`crawler_service.py`)** — if the unit isn't in the catalogue, it goes out to the EU registry online and to the manufacturers' websites to find it, then files the result for next time.
> 6. **Websites (`manufacturer_scraper.py`)** — 19+ brand sites that are searched automatically.
>
> A key design point worth mentioning: the "reading" step runs in a **separate, isolated helper process**. If the reading software ever crashes (it can, on this Mac), the main app stays alive and simply starts a new helper. So the tool never goes down because of an OCR hiccup.
